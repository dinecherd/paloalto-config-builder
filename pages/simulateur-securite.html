    Étape 2 · Rulebase

    L'ordre des règles change tout

    Les règles sont évaluées de haut en bas ; dès qu'une règle correspond, les suivantes ne sont plus évaluées. intrazone-default (allow) et interzone-default (deny) restent toujours en bas et, par défaut, ne journalisent pas.

    Commit Status
    Shadowing (règle masquée)Une règle placée plus haut, plus générale, « fait de l'ombre » à une règle plus bas : celle-ci ne sera jamais atteinte. Le commit le signale dans l'onglet Rule Shadow de la fenêtre Commit Status. Corrigez en réordonnant ou en affinant.
    Ajout d'une règleComme dans la WebUI : si une règle est sélectionnée, Add insère la nouvelle règle juste en dessous ; sinon au-dessus des règles par défaut. Les numéros de ligne ne suivent pas la règle quand on la déplace.
    Règles par défautOn ne peut ni les déplacer ni les supprimer, seulement les Override (ex. Lab 6 : cocher Log at Session End sur interzone-default pour voir les flux refusés dans le Traffic log).

    Étape 4 · CLI

    La même règle en CLI PAN-OS

    Commandes générées en direct à partir du constructeur (mode configuration). Les objets nécessaires sont créés avant la règle ; la position suit celle de votre règle dans la rulebase ci-dessus.

    Rappel · Flow logic (M06)

    Où intervient la règle de sécurité ?

    Ordre simplifié du traitement d'un nouveau paquet (diapo « Flow Logic of the Next-Generation Firewall »).

    Session existante ?

    Si le paquet appartient à une session déjà établie, il est traité directement (fast path).

    Zone source

    Déterminée par l'interface d'entrée. Zone Protection / DoS Protection.

    Forwarding lookup

    PBF puis route → interface de sortie → zone de destination, avec vérification DNAT (zone post-NAT).

    Security Policy check

    Sur les adresses pré-NAT. À ce stade l'application n'est pas encore connue (App-ID ignoré).

    Session créée

    Attribution d'un Session ID. La politique NAT a été évaluée ; elle sera appliquée à la sortie.

    App-ID

    L'application est identifiée ; la règle de sécurité est réévaluée avec l'application réelle.

    Content-ID

    Les Security Profiles attachés à la règle allow inspectent le contenu (AV, Anti-Spyware, Vuln, URL, File Blocking, WildFire).

    Forward

    Ré-encryption si déchiffré, NAT appliquée, paquet transmis.

    Règle de sécurité + NAT

    Règle d'or EDU-210 (M07) : dans une règle de sécurité, les adresses IP sont pré-NAT (celles du paquet d'origine) et la zone de destination est post-NAT (celle où se trouve réellement l'hôte final).

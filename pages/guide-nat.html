    Les types de NAT sur PAN-OS

    Source NAT : en général pour que les utilisateurs internes (IP privées) sortent vers Internet. Destination NAT : en général pour donner accès depuis l'extérieur à un serveur interne.

    Source NAT — on change l'IP source

    🔀 Dynamic IP and Port DIPP

    Plusieurs clients partagent la même IP publique grâce à des ports source différents (PAT). L'adresse traduite peut être l'Interface Address ou une Translated Address (objet / pool).

    Oversubscription (même couple IP:port réutilisé vers des destinations différentes) : Device › Setup › Session › Session Settings (8x / 4x / 2x).

    🎟️ Dynamic IP

    Traduction 1-pour-1 de l'IP seulement (pas du port) : chaque IP privée prend la prochaine adresse disponible du pool. Le pool peut s'épuiser.

    📌 Static IP

    Traduction 1-pour-1 fixe : l'IP source change, le port source reste identique. Supporte l'option Bi-directional : une règle DNAT implicite inverse est créée (utile pour un serveur qui émet ET reçoit).

    Destination NAT — on change l'IP destination (et parfois le port)

    🎯 Static IP

    1-pour-1 fixe vers l'IP du serveur ; le port de destination reste inchangé, sauf si on renseigne Translated Port.

    🔢 Port translation

    Quand le serveur écoute sur un port autre que le port « connu ». Champ Translated Port de la section Destination Address Translation. Astuce slide M07 : service-http couvre TCP 80 et 8080.

    🌀 Dynamic IP (DNAT)

    Destination traduite vers un FQDN, un objet ou un groupe d'adresses — pour un serveur à IP attribuée par DHCP, ou plusieurs serveurs (Session Distribution).

    U-turn NAT (hairpin)Des utilisateurs internes joignent un serveur interne par son IP publique. La règle DNAT doit alors avoir comme zone source la zone interne (ex. Users_Net) et comme zone de destination la zone de l'IP publique (ex. Internet), même si le paquet ne sort jamais vers Internet. Si le client et le serveur sont dans la même zone, ajoutez aussi un Source NAT (vers l'IP d'interface du firewall) pour que la réponse du serveur repasse par le firewall au lieu de revenir directement au client.
    02

    Où intervient le NAT dans le traitement ?

    La politique NAT est évaluée sur le paquet original, avant la politique de sécurité ; la traduction n'est appliquée qu'à la sortie.

    1. Zone sourceInterface d'entrée.
    2. Route lookupSur l'IP de destination originale → zone de destination pré-NAT.
    3. NAT policyTop-down, 1ʳᵉ correspondance, sur le paquet original (zones pré-NAT).
    4. Si DNATNouveau route lookup sur l'IP traduite → zone post-NAT.
    5. Security policyIP pré-NAT + zone de destination post-NAT.
    6. App-ID / Content-IDInspection, Security Profiles.
    7. EgressTraduction appliquée, paquet transmis.
    Une règle NAT n'autorise rienElle traduit seulement. Il faut toujours une règle de sécurité qui autorise le flux.
    Première correspondance seulementLes règles NAT sont évaluées de haut en bas : une seule règle NAT s'applique à une session. Placez les DNAT / règles spécifiques au-dessus des SNAT génériques.

    Tuto B : Destination NAT vers le serveur web Extranet

    Lab 7 : on crée une adresse NAT 192.168.1.80 prise dans le réseau Users_Net. Quand Client-A (192.168.1.20) s'y connecte, le firewall traduit la destination vers le serveur web 192.168.50.80 de la zone Extranet.

    Destination Zone = Users_Net, et non Extranet : l'IP 192.168.1.80 « réside » sur le firewall dans le réseau de ethernet1/2, donc dans la zone Users_Net.
    Pourquoi pas « Extranet » alors que le serveur est dans l'Extranet ?
    La règle NAT est comparée au paquet original. À son arrivée, ce paquet est destiné à 192.168.1.80 ; le lookup de routage place cette IP dans 192.168.1.0/24 (ethernet1/2) → zone Users_Net. Le firewall ne connaîtra la zone Extranet qu'après avoir trouvé la règle NAT et traduit l'adresse. Même logique sur Internet : pour publier un serveur, la destination zone de la règle DNAT est la zone de l'IP publique (ex. Internet). Le firewall répond automatiquement aux requêtes ARP pour une IP NAT appartenant au sous-réseau de l'interface.

    Exemple fictif : le serveur écoute sur TCP 8080 mais les clients Internet utilisent l'IP publique 203.0.113.21 en TCP 80.

    • NAT · Original Packet : Source Zone Internet, Destination Zone Internet (zone de l'IP publique), Destination Interface ethernet1/1, Service service-http, Destination Address 203.0.113.21.
    • NAT · Translated Packet : Destination Address Translation Static IP, Translated Address 192.168.50.80, Translated Port 8080.
    • Sécurité : Source Zone Internet → Destination Zone Extranet (post-NAT), Destination Address 203.0.113.21 (pré-NAT), Application web-browsing, Service service-http (TCP 80 et 8080, comme le rappelle la slide M07).

    Dépannage NAT

    SymptômeCause probableCorrection
    Ping Internet autorisé mais sans réponsePas de Source NATRègle Inside_Nets_to_Internet (DIPP vers 203.0.113.20).
    DNAT ne correspond pasDestination Zone = zone du serveur (Extranet) au lieu de la zone de l'IP NATMettre la zone pré-NAT (Users_Net dans le lab, Internet pour une IP publique).

    Une autre règle NAT est appliquéeOrdre top-down : une SNAT générique au-dessusPlacer la règle spécifique plus haut ; vérifier avec test nat-policy-match.

    Encadré CLI : les deux règles du Lab 7

    Mode configuration (configure). Vérifiez toujours la syntaxe avec Tab / ?.

    CLI · mode configuration 
    configure

# A) Source NAT DIPP
set rulebase nat rules Inside_Nets_to_Internet nat-type ipv4 from [ Users_Net Extranet ] to Internet to-interface ethernet1/1 source any destination any service any
set rulebase nat rules Inside_Nets_to_Internet source-translation dynamic-ip-and-port interface-address interface ethernet1/1 ip 203.0.113.20/24
set rulebase nat rules Inside_Nets_to_Internet description "Translates traffic from Users_Net and Extranet to 203.0.113.20 outbound to Internet"

# B) Destination NAT
set rulebase nat rules Dest_NAT_To_Webserver nat-type ipv4 from Users_Net to Users_Net to-interface ethernet1/2 source any destination 192.168.1.80 service any
set rulebase nat rules Dest_NAT_To_Webserver destination-translation translated-address 192.168.50.80
# (variante port translation : ... destination-translation translated-address 192.168.50.80 translated-port 8080)
